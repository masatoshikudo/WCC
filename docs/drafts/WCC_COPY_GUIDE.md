## 1. 語り手ペルソナ(v2 から継承)

### 定義

> **WCC は、2人の擬似親友として、2人に語りかける。**

WCC というサービス自体が「結婚式当日にそこにいる親友のような存在」として機能することを、コピーで体現する。

これは「文体と感情温度の設定」であり、現実の関係性の描写ではない。
WCC は初対面のサービスである事実は変わらない。

### 重要な区別

- ❌ **誤った理解**: 親友がサービスを紹介している
- ⭕ **正しい理解**: サービス自体が擬似親友として喋っている

### 想定読者

主な想定読者は **花嫁** であるため、語り手も同性として設計する(ジェンダーをコピーから排除する目的)。
ただし「同性の親友」という設定はあくまで温度感の指針であり、コピー上で「私は女性です」のような明示はしない。

### 語り手の感情と性質

- 2人の関係と愛を、心から祝福している
- 感情が溢れる・涙もろい
- 「最高に幸せだから!」と興奮気味に伝える温度感
- 押し売りしない。でも「これ絶対やったほうがいい」という確信がある
- 業界の専門家ではなく、2人の幸せを願う人間として喋る

### 禁止(ペルソナ起因)

以下の表現は「過去の関係性の嘘」になるため完全禁止:

- 「ずっと」「いつも」「見てきた」「知っている」
- 「あなたのことを思うと」(個人的な関係を示唆)
- 「これまでの」「これからも」(継続的な関係の示唆)

WCC は当日初めて 2人 に会う擬似親友。過去の記憶や関係性は持たない。

## 2. 中心軸: 「明日の2人」(v3 から継承)

### 定義

WCC のブランドキャッチフレーズの中心軸は **「明日の2人」**。

これは以下を同時に指示する:
- **時間軸**: 結婚式の翌日(朝〜夕方〜夜の全時間帯を含む幅広い「明日」)
- **人格指示**: 動画を受け取る側の「明日の2人」(読者の「今の2人」とは別)
- **手紙的なニュアンス**: 「明日の2人へ」という宛名のような響き

### v2 「翌朝」軸からの変更経緯

v2 までは「翌朝・ふたり・余韻」を中心軸としていたが、以下の事業実態との齟齬が判明:

- WCC は撮影終了から 24 時間以内納品が約束
- 朝〜昼撮影 → 翌朝の納品は可能(v2 軸通り)
- 夕方〜夜撮影(二次会付き添い等) → **翌朝には間に合わない**(夜以降の納品)

「翌朝、2人で観る」を約束として打ち出すと、撮影スケジュール次第で守れなくなる。BtoC で約束を守れない表現は信頼毀損につながる。

そのため v3 では「翌朝」を全面廃止し、すべての撮影パターンで成立する「明日の2人」軸に変更した。

### 「明日の2人」が指す体験

Masatoshi(事業主)が言語化した想定体験:

- **シーン 1**: ホテルでのチェックアウト前(11 時頃)
  - 朝食、ふたりでくつろぐ時間
  - 1 本目の動画が届く
  - まだ昨日の余韻の中にいる
- **シーン 2**: 日常に戻る道すがら(昼〜夕方)
  - チェックアウト後、段々と日常に戻っていく
  - 縦動画が手元にある = 余韻を引き伸ばす装置
- **シーン 3**: SNS 投稿 → ゲストの夕方〜夜の閲覧ピーク(17:00〜21:00)
  - ゲストが仕事・家事の合間に観る
  - 列席者全員で「昨日のあの瞬間」を再体験
  - 2人の SNS アカウントに同時投稿で幸せな瞬間がアーカイブされる

### コピーでの扱い

「明日の2人」は ヒーロー H1・フッター CTA H2 など **詩的キャッチコピー** で中心的に使う。
本文では「次の日の朝」「朝起きたら」「24 時間以内」など、具体的な時間描写と使い分ける。

## 3. 事業実態と整合する約束原則(v3 から継承、v4 で軽微追加)

### 原則

コピーは事業実態を超える約束をしない。具体的な数値・時間・場所・本数を確定的に書くと、プラン構成や運用の変化に追従できなくなる。

### 守るべきルール

1. **具体数値を確定的に書かない**
   - ❌ 「1 本届けます」(1 本固定 = Extras で本数が変わる場合に整合しない)
   - ❌ 「翌朝届きます」(撮影時間で守れないケースあり)
   - ❌ 「11 時に届きます」(運用上の余裕がない)
   - ⭕ 「縦動画を届けます」(本数を明示しない)
   - ⭕ 「24 時間以内に届きます」(プラン上の確定値)

2. **抽象的な機能描写を優先**
   - ❌ 「2 本の縦動画」 → ⭕ 「縦動画」「ふたりだけの一本」
   - ❌ 「4 時間撮影」(個別ページでは OK、ヒーローでは抽象化)

3. **約束は Pricing 詳細セクションで明示**
   - ヒーローでは詩的・抽象的に
   - Pricing 詳細では具体数値(24 時間以内・4 時間撮影・9:16 縦動画 2 本)を明記

4. **無料を約束しない**(v4 追加)
   - ❌ 「ご相談は無料」(将来の有料相談導入時に整合しなくなる)
   - ⭕ 「日程未定の段階からご相談いただけます」(ハードルの低さを別の言い方で表現)
   - 詳細はセクション 4「事業フローとコピーの責務区分」を参照

### 過去の失敗事例

- **「翌朝、ふたりで観る」**(v2): 撮影時間によっては守れない約束だった
- **「ひとつ届ける」**: Extras で本数増加時に整合しない可能性
  - → v3 では「縦動画を届けます」に修正
- **「ご相談は無料」**(v3 まで): 業務フロー変更で旧フロー(無料 ZOOM 相談)を連想させる表現になり、v4 で廃止

## 4. 事業フローとコピーの責務区分(v4 新規)

### 原則

事業フロー(業務工程の順序、運用上の手順)は WCC_PRODUCT.md を単一ソースとする。
コピーガイドは、事業フローを言葉として表現する際の「言い回し規定」に責務を限定する。

この区分により、業務フローの変更が発生したとき、WCC_PRODUCT.md だけを更新すれば、コピーガイドの更新は不要(言い回し規定が変わらない限り)になる。

### 責務区分

| 責務 | 担当ドキュメント |
|---|---|
| 事業フローの定義(順序・工程・実行内容) | WCC_PRODUCT.md |
| 事業フローを表現するコピーの言い回し | コピーガイド(本ドキュメント) |
| 業務文(メール、フォーム自動返信、契約)の文面テンプレート | 別途検討(現状は WCC_PRODUCT.md 内に簡易記載) |

### 言い回し規定(コピーガイドの責務)

事業フローに登場する用語の表記・言い換えを統一する。

| 用語 | 推奨表記 | 文脈と備考 |
|---|---|---|
| ご決済 / お支払い | 業務文では「ご決済」、本文・FAQ では文脈に応じて使い分け | 「ご決済完了をもってご予約確定」のように業務文では「ご決済」が自然 |
| お見積もり | 「お見積もり」(送り仮名あり) | 「お見積り」と表記揺れさせない |
| 請求書 | 「請求書」または「請求書 URL」 | Stripe の決済リンクを指す場合も「請求書 URL」と表現 |
| ご予約確定 | 「ご決済完了をもってご予約確定」 | 「決済完了」と等価。動作主体が読者の場合は「ご予約確定」を優先 |
| ZOOM 詳細打ち合わせ | 「ZOOM 詳細打ち合わせ」または「ZOOM での打ち合わせ」 | 「ZOOM ミーティング」「オンライン打ち合わせ」と揺れさせない |
| 公式 LINE | 「公式 LINE」(半角スペース) | 「LINE 公式アカウント」と書き換えない |

### 「無料相談」を約束しない原則

v3 までは「ご相談は無料」と表記していたが、v4 では以下の理由で「無料」の明示を避ける:

- 業務フロー変更により、無料 ZOOM 相談を廃止(2026-05-07)
- /book フォームでの問い合わせおよびお見積もりは無償で提供しているが、これを「無料相談」と表現すると旧フロー(無料 ZOOM 相談)を連想させる
- 「無料」を約束として書くと、将来の有料相談導入時に整合しなくなる(セクション 3「事業実態と整合する約束原則」と同じ思想)

代替表現:

- ❌「ご相談は無料・日程未定でも受け付けています」
- ⭕「日程未定の段階からご相談いただけます」

「ハードルの低さ」を「無料」ではなく「日程未定でも OK」「気軽さ」で表現する方針。

### 業務フローの記述箇所

具体的な業務フロー(フォーム → 見積もり → 請求書 → 決済 → 公式 LINE → ZOOM → 当日)の工程定義は、本ガイドでは詳述しない。
最新のフロー定義は WCC_PRODUCT.md を参照。

ただし、以下の場合はコピーガイド側で取り扱う:

1. **言い回しの統一が必要な場面**: 上記「言い回し規定」表で対応
2. **コピー全体の温度・トーンとの調整**: セクション 14「セクション別コピー方針」で対応
3. **NG / OK 例として参照する場合**: セクション 15「コピーの NG 例 / OK 例」で対応

## 5. 感情温度のルール(v2 から継承)

### 基本原則

**前提**: 読者(花嫁・婚約カップル)は人生で最も幸せな時期にいる。
その温度感に合わせた、祝福に満ちたコピーでなければ響かない。

### 感情温度のサンプル

このガイドが目指す感情温度の基準として、以下のサンプルを参照する:

> 「次の日見てみて、最高に幸せだから!」
> 「朝起きたら見てみて、最高に幸せだから!」

この温度感が、すべての本文・キャッチコピーで再現されるべき水準。

### ルール

#### 1. 否定形を完全排除

- ❌ 「〜ではありません」「〜しなくてもいい」「〜は必要ありません」
- ❌ 「〜ではなく、〜」(比較否定)
- ❌ 「〜じゃなくて」(口語の否定形)
- ⭕ 「〜です」「〜があります」「〜できます」

#### 2. 比較優位を使わない

- ❌ 「写真は瞬間を、動画はその日の流れを残します」
- ❌ 「普通のビデオとは違う」
- ⭕ 「2人の目線をそのまま残す」

#### 3. 感情を出していい・むしろ出すべき

- 淡々とした説明調は禁止
- 感嘆符「!」を本文で **多めに** 使う
- フィラー「ほんとに」「絶対」「だから」「全然」を積極的に使う
- 「〜から!」「〜よ!」「〜だから!」のような口語的感情表現を許容
- ただし「感動」「奇跡」「最高の」(断定)は引き続き禁句

#### 4. 祝福を前提にする

- 読者が「幸せな状況にいる」ことを前提に書く
- 「もし〜なら」「〜に悩んでいる方へ」のような問題提起型の書き出しは使わない

## 6. 二人称のルール(v3 から継承)

### 原則

擬似親友が呼ぶなら、呼び方は **「2人」** が中心(v2 では「ふたり」中心だったが、v3 で「2人」を主とする)。

### 詳細規定(3 種使い分け)

| 用途 | 表記 | 理由 |
|---|---|---|
| ヒーロー・キャッチコピー・詩的見出し・SNS ネイティブな短文 | **2人** | 視覚的に短く潔い、若年語彙、SNS 文化との親和性 |
| 本文・解説・サービス説明 | **ふたり** | 親友としての温度感、本文に読みやすい |
| 業務文・契約・フォーマル | **お二人** | 業務上の敬意 |
| 募集・招待・「最初の参加者」を呼びかける文脈(例: Founding Couple ページのヒーロー) | **おふたり** | 敬意を出しつつ、業務文ほど事務的にならない中間温度 |
| 「あなた」 | **禁止** | 個人への冷たい語りかけになる |

### 具体例

- ヒーロー H1: 「明日の2人へ」✅(詩的・短文・SNS ライク)
- 本文: 「ふたりのそばにいる」✅(解説・温度)
- 本文: 「ふたりだけの一本」✅
- Bespoke 業務文: 「お二人専用のプランをお見積もりします」✅
- Founding Couple ヒーロー H1: 「最初のおふたりへ」✅(募集・招待・中間温度)
- Do I need: 「あなたに向いています」❌ → 「ふたりに合うかも!」✅

### 表記の選び方

迷ったら:
- 短くしたい・SNS っぽくしたい → 「2人」
- 温度を出したい・親密に・本文 → 「ふたり」
- 募集・招待・最初の参加者への呼びかけ → 「おふたり」
- 業務的・契約的 → 「お二人」

## 7. 語彙レベルのルール(v2 から継承、v4 で 7.1 追加)

### 基準: 頭のいい高校 2 年生

実際の婚礼年齢(20 代後半〜30 代)よりも下の語彙を意識する。
理由: あまねく価値観や知性の方に理解してもらうため。伝わることを最優先する。

### 漢字を開く

| ❌ 漢字 | ⭕ ひらがな |
|---|---|
| 観る | 見る |
| 上げる(SNS に〜) | あげる |
| 仕立てる | つくる / する |
| 観返す | 見返す |

### 平易な単語に置き換える

| ❌ 難しい単語 | ⭕ 平易な単語 |
|---|---|
| 補完的 | (使わず削除) |
| 内訳 | 中身 |
| 目安 | だいたい / めやす |
| 興奮 | 気持ち |
| 余韻(本文では) | 気持ち / あの感じ |
| 検討 | 考える |
| 案内する | 教える |
| 共有する | 教える / 送る |

### 専門用語の扱い

業界用語は最小限:

許容: ウェディング / カメラマン / ムービー / SNS / iPhone / 9:16 縦動画
禁止: クリエイト / クリエイター / コンテンツクリエーション / ストーリーテリング

### 7.1 表記統一規定(v4 新規)

固有名詞、英字、数値の表記を統一する。Phase B(2026-05-07)で運用上の必要から確定。

#### 固有名詞

| 表記 | ルール | 備考 |
|---|---|---|
| 公式 LINE | 「公式」と「LINE」の間に半角スペース | 文中でも前後に半角スペース必要(例:「公式 LINE で」) |
| ZOOM | 全大文字 | 「Zoom」「zoom」と表記しない |
| Stripe | そのまま英字、業務文・FAQ で使用可 | 一般読者向け本文では避ける(代わりに「請求書 URL」など) |
| iPhone | 大文字 P | 「iphone」「IPhone」と表記しない |
| DJI Osmo Pocket | 「DJI」「Osmo」「Pocket」の間に半角スペース | 機材説明で使用、ヒーロー等では使わない |

#### 数値表記

| 表記 | ルール | 例 |
|---|---|---|
| 4 時間 | 数値と単位の間に半角スペース | 「4 時間撮影」「4 時間連続のコンテンツ撮影」 |
| 24 時間 | 数値と単位の間に半角スペース | 「24 時間以内」「24 時間以内の納品」 |
| 9:16 | コロンは半角、前後にスペースなし | 「9:16 縦動画」「9:16 縦動画 2 本」 |
| 176,000 円 | 三桁区切りカンマ、円の前にスペースなし | 「176,000 円(税込)」 |

#### 英字併記

英字と日本語の境界には半角スペースを入れる:

- ⭕ 「ご決済後の ZOOM ミーティング」
- ❌ 「ご決済後のZOOMミーティング」
- ⭕ 「公式 LINE で」
- ❌ 「公式LINEで」
- ⭕ 「iPhone または DJI Osmo Pocket で記録」
- ❌ 「iPhoneまたはDJI Osmo Pocketで記録」

#### 例外

詩的キャッチコピーで意図的にスペースを詰める場合は許容する(視覚的リズムのため):

- 「明日の2人へ」 ← 数値「2」と「人」の間にスペースなしが原則(ペルソナ規定の一部)
- 「9:16 縦動画」 ← 「9:16」の中はスペースなし

ただし、本文・業務文では原則どおり半角スペースを入れる。

## 8. 文体トーンのルール(v2 から継承)

### 許容する表現パターン

| パターン | 例 | 機能 |
|---|---|---|
| 問いかけ | 「次の日の朝、2人で見れる動画って、手元にある?」 | 読者の自分事化 |
| 状況描写 | 「朝起きたら、コーヒー淹れて、ふたりで見る」 | 体験の先取り |
| 感情的な短文 | 「絶対、泣くから!」「最高に幸せだから!」 | 温度の頂点 |
| 控えめな機能描写 | 「全部そこにいて、全部拾う」 | 在り方の提示 |
| 親友の呼びかけ | 「見てみて!」「話そう!」「チェックして!」 | 距離の近さ |

### 禁止する表現パターン

| パターン | 例 | 理由 |
|---|---|---|
| 否定形 | 「〜ではない」「〜じゃなくて」 | 感情温度を下げる |
| 比較優位 | 「普通の〜とは違い」 | 他者を否定する |
| 営業定型句 | 「お気軽に」「ご不明な点は」「何なりと」 | 業務的・冷たい |
| 命令形(業務的) | 「ご検討ください」「お申し込みください」 | 押し売り感 |
| 問題提起型 | 「〜に悩んでいませんか?」 | 祝福の文脈と合わない |
| 大げさな感情表現 | 「感動」「奇跡」「最高の瞬間」「永遠に」 | BRAND v2 禁句 |
| 過去関係性の示唆 | 「ずっと」「見てきた」 | ペルソナの嘘になる |

### 文体の口語化

- 「〜です・〜ます」を基本としつつ、感情の頂点では「〜から!」「〜よ!」などの口語的語尾を許容
- 「〜である」「〜だ」調は禁止

## 11. 句読点ルール(v2 から継承)

### 句点「。」

- 見出し(H1 / H2): なし
- 本文・説明文・案内文: あり
- キャッチコピー・詩的ステートメント: なし

### 読点「、」

- 文法的な区切りに使う
- 見出しでは詩的リズムのために使ってよい
- 1 文に最大 3 個まで

### 感嘆符「!」

- 見出し・キャッチコピー: 使わない
- 本文: **多めに使う**(1 段落に 1〜3 個目安)
- フッター CTA・呼びかけ: 積極的に使う

### その他

| 記号 | ルール |
|---|---|
| 中黒「・」 | 並列表記は読点で表現が第一推奨 |
| 疑問符 | 半角「?」を使う |
| 括弧() | 説明補足に使う(全角) |
| 「」 | 引用・セリフに使う |

#### 各セクションの方針

##### ページヘッダ帯

「Pricing」というページ性質上、業務情報の入口として機能する。ハードルの低さを伝えるが、「無料」を約束しない(セクション 4「無料相談を約束しない原則」参照)。

- ⭕ 「日程未定の段階からご相談いただけます」
- ❌ 「ご相談は無料・日程未定でも受け付けています」

##### Extras(追加オプション)

5 項目の業務情報を、価格と機能のみで簡潔に提示する。詩的描写・温度感は不要。

- 各項目は `name`(項目名)+ `price`(価格表記)+ `description`(/pricing 表示用説明文)で構成
- description はコピーガイドの「Pricing トーン(中温・正確)」に準じて、機能的・正確に書く
- 例: 「DJI Osmo Pocket を最大 2 台までお貸出し」

##### Bespoke(オーダーメイド)

スタンダードプランで収まらない要件への対応窓口。「初期設計」のような業務専門用語は読者には伝わりにくいため、表に出さない。

- 共通項(基本 4 時間撮影 + クリエイター 1 名)を明示してスタンダードとの連続性を示す
- 「メニューにないご要望にも、お二人専用のプランとして」という枠組みで価値を表現
- 例示は具体的に複数列挙(2 日撮影、海外挙式、企業イベント、複数会場移動など)
- 末尾で「お見積もりプロセス」を明示

##### 再利用コンポーネント

LP トップで使われている `HomePricingSection` `HomeServiceFlowSection` `HomeFaqSection` は、/pricing でも同じコンポーネントを再利用している。これらの方針はセクション 14(LP トップ)と同じ。
